The Blue Bird Philosophy

Stop wasting time configuring CORS, security headers, database connections, and authentication flows. Blue Bird provides an opinionated, highly efficient core structure allowing you to focus on writing clean business logic. Nginx handles the static frontend directly from the filesystem, Express handles the backend APIs. Includes a preconfigured Docker stack with Nginx reverse proxy, Redis cache, and PM2 cluster scaling.

Decoupled & Multi-Platform

Nginx natively serves static frontend assets and extensionless HTML pages from frontend/. Express owns the API layer, allowing you to easily target Web, Mobile (Capacitor, Cordova), and Desktop (Electron, Tauri) using the exact same backend logic.

Strong Logic & Low Footprint

Separating static file delivery to Nginx keeps your Express API layer focused purely on high-performance business logic, data validation, and authentication with extremely low CPU, RAM, and disk consumption.

Built-in Orchestration

Includes a comprehensive Docker Compose CLI wrapper to bootstrap, build, stop, and clean dev and production environments with zero manual scripting.

1 Installation & Setup

Get your project up and running with Blue Bird in three simple steps

1. Installation

Install the framework package in your project directory 

npm install @seip/blue-bird

2. Initialize Project

Run the initialization tool to generate the default application directory structure 

npx blue-bird

This generates .env, backend/, frontend/, index.js, and sets type: "module" automatically.

3 Application Class (App)

Initializes the framework server, setting up default parsers, static routes, secure CORS policies, cookies, and route handlers. 

import App from "@seip/blue-bird/core/app.js";
import routerApi from "./backend/routes/api.js";

const app = new App({
  port: process.env.PORT || 3000,
  host: "http://localhost",
  routes: [routerApi],
  cors: [],
  middlewares: [],
  logger: false
});

app.run();

Standardized Response Helpers

Every Express response object is automatically enhanced with standardized API response methods: 

// 1. Success Responses
res.ok(user, "User fetched successfully");       // HTTP 200 { status: "success", message, data: user }
res.created(newItem, "Item created");            // HTTP 201 { status: "success", message, data: newItem }
res.success(data, "Custom success", 200);

// 2. Error Responses
res.badRequest("Invalid input", [{ field: "email", message: "Email is required" }]); // HTTP 400 { status: "error", message, errors }
res.unauthorized("Authentication required");     // HTTP 401 { status: "error", message }
res.forbidden("Access denied");                  // HTTP 403 { status: "error", message }
res.notFound("Resource not found");              // HTTP 404 { status: "error", message }
res.serverError("Internal failure");             // HTTP 500 { status: "error", message }
res.error("Custom error", 422, errors);

// 3. Paginated Response
res.paginate(usersArray, { page: 1, limit: 10, total: 100 }, "Users page 1");
// Responds: { status: "success", message: "Users page 1", data: [...], pagination: { page: 1, limit: 10, total: 100, totalPages: 10 } }

AppError & Automatic Async Error Handling

All GET/POST/PUT/DELETE routes created with Blue Bird's Router automatically catch async errors and pass them to the global error handler. You can throw operational AppError instances anywhere without wrapping your routes in try/catch blocks: 

import { AppError } from "@seip/blue-bird/core/app.js";

router.get("/users/:id", async (req, res) => {
  const user = await db.query("SELECT * FROM users WHERE id = ?", [req.params.id], "return_row");
  
  if (!user) {
    throw new AppError("User not found", 404); // Caught automatically and returned as standard JSON error
  }
  
  return res.success(user);
});

Standalone Express Frontend Serving (Without Docker / Nginx)

If your application does not use Docker, Nginx, MySQL, or Redis (e.g. standalone Express apps, Express + SQLite, or pure Node.js environments), or if you want Express to serve static assets directly as a fallback, you can pass the static configuration parameter to new App(...). 

const app = new App({
  routes: [routerApi],
  cors: [],
  middlewares: [],
  host: "http://localhost",
  port: process.env.PORT || 3000,
  logger: false,
  // Configure static asset serving directly inside Express
  static: {
    path: "../frontend", // relative path to static files directory
    options: {}           // express.static options
  }
});

app.run();

Under the hood, core/app.js evaluates if (this.static.path) and automatically mounts express.static with custom security headers: 

if (this.static.path) {
  this.app.use(
    express.static(path.join(__dirname, this.static.path), {
      ...this.static.options,
      setHeaders: (res) => {
        res.setHeader("X-Powered-By", "Blue Bird");
        res.setHeader("Cache-Control", "public, max-age=31536000, immutable");
      },
    })
  );
}

5 Validation (Validator)

Checks request payload schemas automatically. It cleanses strings to prevent cross-site scripting (XSS) by default, and responds with a standard 400 Bad Request validation array on failures. 

import Validator from "@seip/blue-bird/core/validate.js";

const userSchema = {
  email: { required: true, email: true },
  password: { required: true, min: 8 },
  bio: { required: false } // Cleansed from XSS scripts automatically
};

const validateUser = new Validator(userSchema, "en");

routerApi.post("/users", validateUser.middleware(), (req, res) => {
  res.json({ success: true });
});

6 Password Hashing (Hash)

Provides secure, timing-safe password hashing using native node:crypto.scrypt (zero external npm dependencies required). It also seamlessly integrates with bcrypt when the package is installed or when verifying existing bcrypt hashes. 

import Hash from "@seip/blue-bird/core/hash.js";

// 1. Hash a password with scrypt (default, random salt)
const hash = await Hash.make("mySecretPassword123");
// Generated format: $scrypt$N=16384,r=8,p=1$salt$hash

// 2. Verify password with constant-time comparison
const isValid = await Hash.verify("mySecretPassword123", hash); // true or false

// 3. Convenience alias
const check = await Hash.check("mySecretPassword123", hash);

// 4. Using bcrypt driver (requires: npx blue-bird add bcrypt)
const bcryptHash = await Hash.make("mySecretPassword123", { driver: "bcrypt", rounds: 10 });

7 Authentication (Auth)

Implements stateless and Redis-backed session authentication. Token payloads are encrypted with military-grade AES-256-GCM algorithms and transmitted via secure HTTP-Only cookies or Authorization headers. 

import Auth from "@seip/blue-bird/core/auth.js";

// 1. Protect API routes (returns 401 JSON on failure)
router.get("/api/profile", Auth.protect(), (req, res) => {
  res.json({ user: req.user });
});

// 2. Protect Web Pages with custom redirect
router.get("/dashboard", Auth.protect({ redirect: "/login", key: "user", cookieKey: "auth" }), (req, res) => {
  res.send(`
Welcome ${req.user.name}
`);
});

// 3. Log in user, set AES-256-GCM cookie & sync session in Redis
router.post("/api/login", async (req, res) => {
  const user = { id: 1, name: "John Doe", role: "admin" };
  await Auth.login(res, user, "auth", {
    expiresIn: "7d",
    cookie: { sameSite: "strict" }
  });
  res.json({ success: true });
});

// 4. Log out user, clear cookie & delete session in Redis
router.post("/api/logout", async (req, res) => {
  await Auth.logout(res, "auth", {}, req);
  res.json({ success: true });
});

// 5. Utility: Generate & Verify Encrypted JWT Tokens manually
const token = Auth.generateToken({ id: 10 }, process.env.JWT_SECRET, "2h");
const payload = Auth.verifyToken(token, process.env.JWT_SECRET);

// 6. Utility: Raw AES-256-GCM String Encryption & Decryption
const encrypted = Auth.encrypt({ secretData: "supersecret" }, process.env.JWT_SECRET);
const decrypted = Auth.decrypt(encrypted, process.env.JWT_SECRET);

8 Cache Module (Memory & Redis)

Provides high-performance response and data caching. Configured via CACHE_MODE in .env:

  • CACHE_MODE="memory": Fast local RAM cache inside Node.js with auto-TTL cleanup. Zero network latency (Default).
  • CACHE_MODE="redis": Distributed cache across containers with auto-fallback to memory if Redis is down.
  • CACHE_MODE="none": Bypasses caching.

import Cache, { getRedisClient } from "@seip/blue-bird/core/cache.js";

// 1. Automatic Route Caching Middleware (JSON or HTML for 60 seconds)
router.get("/api/statistics", Cache.middleware(60), (req, res) => {
  res.ok({ computedData: [10, 20, 30] });
});

// 2. Programmatic Cache Manipulation & Invalidation
await Cache.set("custom_key", { data: "value" }, 120);
const cachedData = await Cache.get("custom_key");

// Manually invalidate route cache (e.g. after updating DB)
await Cache.delete("/api/public/config");

// Clear all cache entries (memory & Redis)
await Cache.clear();

// 3. Direct Redis Access for Custom Database & Data Caching (when in redis mode)
router.get("/api/custom-data", async (req, res) => {
  const redis = getRedisClient();
  
  if (redis) {
    const cached = await redis.get("my_custom_key");
    if (cached) return res.ok(JSON.parse(cached));

    const freshData = { time: Date.now(), items: ["A", "B", "C"] };
    await redis.set("my_custom_key", JSON.stringify(freshData), { EX: 120 });
    return res.ok(freshData);
  }

  // Fallback response when Redis is not enabled
  res.ok({ items: ["A", "B", "C"] });
});

9 Helmet Security

Protect HTTP response headers by applying Helmet rules. You can declare Helmet policies per-router. Custom configuration keeps X-Powered-By: Blue Bird headers active by default. 

import App from "@seip/blue-bird/core/app.js";

const apiRouter = new Router("/api");
apiRouter.use(App.helmet()); // Uses default policies

const secureWebRouter = new Router("/web");
secureWebRouter.use(App.helmet({ contentSecurityPolicy: false })); // Disables CSP restrictions

10 Database Module (SQLite, MySQL, PostgreSQL)

Blue Bird includes a unified database wrapper (`core/database.js`) supporting SQLite (better-sqlite3, default), MySQL (mysql2/promise), and PostgreSQL (pg).

SQLite WAL & Concurrency: SQLite is configured with PRAGMA journal_mode = WAL;, PRAGMA busy_timeout = 5000;, PRAGMA synchronous = NORMAL;, and PRAGMA foreign_keys = ON; to eliminate "database is locked" errors and ensure high concurrency with readers and writers.

Supports ? parameter placeholders across all engines (automatically translated to $1, $2, ... for PostgreSQL). 

import { Database, DB_TYPE } from "@seip/blue-bird/core/database.js";

// Instantiate the database connection pool with a custom limit (e.g., 20 connections)
const connection = new Database(20);

// 1. Fetch a single row (SELECT query with ? placeholders works on both MySQL and PostgreSQL)
const user = await connection.query("SELECT * FROM users WHERE id = ?", [123], "return_row"); 

// 2. Fetch rows (SELECT query)
const users = await connection.query("SELECT * FROM users WHERE id = ?", [123], "return_rows"); 

// 3. Fetch rows with 60s Redis query caching enabled
const products = await connection.query("SELECT * FROM products", [], { cache: 60, return_rows: true });

// 4. Debug query execution output
const debug = await connection.query("SELECT * FROM users", [], { debug: true });
// Output:
// [DATABASE DEBUG] SQL: SELECT * FROM users 
// [DATABASE DEBUG] PARAMS: []
// [DATABASE DEBUG] OPTIONS: { debug: true }
// [DATABASE DEBUG] CACHE HIT / MISS

// 5. INSERT query (returns insertId for MySQL, or row ID / rowCount for PostgreSQL)
const newUserId = await connection.query("INSERT INTO users (email) VALUES (?)", ["test@example.com"]);

// 6. Automatic SQL Query Pagination (Runs count query + LIMIT/OFFSET calculation)
const paginated = await connection.paginate(
  "SELECT * FROM users WHERE status = ?",
  ["active"],
  { page: 1, limit: 10, cache: 60 }
);
// Returns: { data: [...], total: 100, page: 1, limit: 10, totalPages: 10 }

// 7. Atomic Database Transactions with Automatic Commit & Rollback
const txUserId = await connection.transaction(async (tx) => {
  const userId = await tx.query("INSERT INTO users (name, email) VALUES (?, ?)", ["Alice", "alice@example.com"]);
  await tx.query("INSERT INTO profiles (user_id, bio) VALUES (?, ?)", [userId, "Developer"]);
  return userId;
});

11 Real-Time WebSockets Engine

Blue Bird includes a built-in high performance WebSocket server wrapper (`core/ws.js`) based on vanilla WebSockets (ws). It runs on the exact same HTTP server and port as Express without requiring socket.io bloat or separate ports.

It features automatic room subscriptions (socket.join / socket.leave), JWT authentication verification, 30-second ping/pong heartbeat to prune dead sockets, and Redis Pub/Sub cluster synchronization so events broadcasted from any Express route are instantly delivered across all PM2 workers. 

import App from "@seip/blue-bird/core/app.js";

const app = new App({ ... });

// 1. Initialize WebSocket server route (/ws) with optional JWT auth validation
const ws = app.websocket({ path: "/ws", auth: true });

ws.onConnection((socket, req) => {
  console.log("Connected user:", socket.user);
  
  // Join a real-time room
  socket.join("lobby");
  
  // Send JSON helper
  socket.sendJSON({ message: "Welcome to Blue Bird WebSockets" });

  socket.on("message", (raw) => {
    // Broadcast to room (synced across PM2 cluster via Redis Pub/Sub)
    ws.broadcast({ room: "lobby", text: raw.toString() }, "lobby");
  });
});

app.run();

2. Broadcasting Real-Time Events from Express API Routes

You can broadcast events to connected WebSocket rooms directly from inside any Express REST endpoint. app.wsManager.broadcast() automatically distributes the message across all PM2 cluster processes via Redis Pub/Sub: 

router.post("/api/comments", async (req, res) => {
  // 1. Save comment into database...
  const comment = { id: 1, text: req.body.text };

  // 2. Broadcast in real time to all WebSocket clients in the "lobby" room
  app.wsManager.broadcast({ type: "NEW_COMMENT", data: comment }, "lobby");

  return res.success(comment, "Comment created");
});

14 Nginx Static Asset Caching

In production, Nginx is configured to explicitly cache static assets (.js, .css, .jpg, .png, etc.) in the user's browser with the Cache-Control header (valid for 1 month).

HTML and API endpoints (/api/*) are not cached by Nginx to ensure they serve dynamic and up-to-date content, relying instead on the Node.js application and Redis for data-layer caching.

VPS Permissions & Security Hardening

Avoid deploying inside /home/user/ due to parent directory traversal restrictions (700/750) and multi-user security risks. Deploy to standard FHS paths like /var/www/<project-name> or /srv/<project-name>.

Nginx runs inside Alpine as an unprivileged user (nginx, UID 101). Static assets should be mounted as read-only (./frontend:/app/frontend:ro) in docker-compose.yml for container-level hardening.

Recommended Permissions Matrix:

/var/www/<project> : chmod 755 (Allows unprivileged Nginx container path traversal)

frontend/ : 755 (dirs) / 644 (files)

node_modules/ : 755 (dirs) / 644 (files) & chmod -R +x node_modules/.bin

.env : chmod 600 (Restricted private access - NEVER 777)

# 1. Set project ownership and standard directory traversal:
sudo chown -R $(whoami):$(whoami) /var/www/my-project && cd /var/www/my-project
chmod 755 /var /var/www /var/www/my-project

# 2. Set directory (755) and file (644) permissions for static assets:
find frontend -type d -exec chmod 755 {} +
find frontend -type f -exec chmod 644 {} +

# 3. Secure node_modules while preserving execution bits in .bin:
find node_modules -type d -exec chmod 755 {} +
find node_modules -type f -exec chmod 644 {} +
chmod -R +x node_modules/.bin 2>/dev/null || true

# 4. Restrict private credentials:
chmod 600 .env
🔧

VPS Troubleshooting Guide (Problems & Solutions)

❌ Problem 1: Static files return 404 / 403 (stat() failed 13: Permission denied)

Cause: Parent directories on host lack +x traversal permission or files lack +r read permission for unprivileged nginx worker.

chmod 755 /var/www/my-project && find frontend -type d -exec chmod 755 {} + && find frontend -type f -exec chmod 644 {} +

❌ Problem 2: npx blue-bird fails with sh: 1: blue-bird: Permission denied

Cause: Blanket chmod 644 stripped execute permissions from binary links in node_modules/.bin/.

chmod -R +x node_modules/.bin

❌ Problem 3: 404 after renaming or recreating project folder (mv / rm -rf)

Cause: Docker volume mounts bind to disk inodes. Recreating the folder desynchronizes active mounts.

npx blue-bird docker stop && npx blue-bird docker start prod

🔍 Diagnostic Commands

Tail real-time Nginx logs or inspect path traversal:

docker compose logs -f nginx
namei -l /var/www/my-project/frontend/css/bluebird.css
