The Blue Bird Philosophy

Stop wasting time configuring CORS, security headers, database connections, and authentication flows. Blue Bird provides an opinionated, highly efficient core structure allowing you to focus on writing clean business logic. Nginx handles the static frontend directly from the filesystem, Express handles the backend APIs. Includes a preconfigured Docker stack with Nginx reverse proxy, Redis cache, and PM2 cluster scaling.

Decoupled Architecture

Nginx natively serves static frontend assets and extensionless HTML pages from frontend/. Express owns the API layer, keeping your backend entirely focused on performance and logic.

Built-in Orchestration

Includes a comprehensive Docker Compose CLI wrapper to bootstrap, build, stop, and clean dev and production environments with zero manual scripting.

1 Installation & Setup

Get your project up and running with Blue Bird in three simple steps

1. Installation

Install the framework package in your project directory 

npm install @seip/blue-bird

2. Initialize Project

Run the initialization tool to generate the default application directory structure 

npx blue-bird

This generates .env, backend/, frontend/, index.js, and sets type: "module" automatically.

3. Available Scripts

Script Command Description
npm run dev node --watch --env-file=.env index.js Express API with file-watcher
npm start node --env-file=.env index.js Production server startup
npm start node --env-file=.env index.js Production server startup

2 Configuration (.env)

Settings are structured inside the `.env` configuration file. Standard variables configure ports, debugging levels, and Docker databases.

3 Application Class (App)

Initializes the framework server, setting up default parsers, static routes, secure CORS policies, cookies, and route handlers. 

import App from "@seip/blue-bird/core/app.js";
import routerApi from "./backend/routes/api.js";

const app = new App({
  port: 3000,
  routes: [routerApi],
  cors: { origin: "http://localhost:3000" },
  rateLimit: { windowMs: 15 * 60 * 1000, max: 100 }
});

app.run();

4 Routing

Do not use native Express routers. Always use Blue Bird's custom Router class wrapper. 

import Router from "@seip/blue-bird/core/router.js";

const router = new Router("/api");

router.get("/users", (req, res) => {
  res.json({ users: [] });
});

export default router;

5 Validation (Validator)

Checks request payload schemas automatically. It cleanses strings to prevent cross-site scripting (XSS) by default, and responds with a standard 400 Bad Request validation array on failures. 

import Validator from "@seip/blue-bird/core/validate.js";

const userSchema = {
  email: { required: true, email: true },
  password: { required: true, min: 8 },
  bio: { required: false } // Cleansed from XSS scripts automatically
};

const validateUser = new Validator(userSchema, "en");

routerApi.post("/users", validateUser.middleware(), (req, res) => {
  res.json({ success: true });
});

6 Authentication (Auth)

Implements stateless JWT authentication. Payload structures are encrypted with military-grade AES-256-GCM algorithms and set inside secure, signed cookies or read from header strings. 

import Auth from "@seip/blue-bird/core/auth.js";

// 1. Protecting API routes (returns 401 on failure)
router.get("/api/profile", Auth.protect(), (req, res) => {
  res.json({ user: req.user });
});

// 2. Logging in and setting session cookies
router.post("/api/login", async (req, res) => {
  const user = { id: 1, name: "John Doe", role: "admin" };
  await Auth.login(res, user);
  res.json({ success: true });
});

// 3. Logging out and clearing cookies
router.post("/api/logout", async (req, res) => {
  await Auth.logout(res);
  res.json({ success: true });
});

7 Cache Middleware

For database or heavy operations, cache the resulting JSON/HTML stream automatically using our routing middleware cache wrapper. 

import Cache from "@seip/blue-bird/core/cache.js";

// Cache this API result for 60 seconds
router.get("/api/statistics", Cache.middleware(60), (req, res) => {
  res.json({ computedData: [10, 20, 30] });
});

8 Helmet Security

Protect HTTP response headers by applying Helmet rules. You can declare Helmet policies per-router. Custom configuration keeps X-Powered-By: Blue Bird headers active by default. 

import App from "@seip/blue-bird/core/app.js";

const apiRouter = new Router("/api");
apiRouter.use(App.helmet()); // Uses default policies

const secureWebRouter = new Router("/web");
secureWebRouter.use(App.helmet({ contentSecurityPolicy: false })); // Disables CSP restrictions

9 Database Module

Blue Bird includes a unified database wrapper (`core/database.js`) supporting MySQL (mysql2/promise) and PostgreSQL (pg). During project setup with npx blue-bird, the CLI interactive wizard asks for your preferred database (none, mysql, or postgres), automatically copying the corresponding Docker Compose template (docker/docker-compose.mysql.yml, docker/docker-compose.postgres.yml, or docker/docker-compose.none.yml) as the root docker-compose.yml.

If connecting to PostgreSQL using native SQL queries, parameter placeholders (`?`) are automatically converted to PostgreSQL `$1, $2, ...` placeholders under the hood, allowing unified query writing across engines. You can also connect without Docker directly by setting DATABASE_URL inside your .env file. 

import { Database, DB_TYPE } from "@seip/blue-bird/core/database.js";

// Instantiate the database connection pool with a custom limit (e.g., 20 connections)
const connection = new Database(20);

// 1. Fetch a single row (SELECT query with ? placeholders works on both MySQL and PostgreSQL)
const user = await connection.query("SELECT * FROM users WHERE id = ?", [123], "return_row"); 

// 2. Fetch rows (SELECT query)
const users = await connection.query("SELECT * FROM users WHERE id = ?", [123], "return_rows"); 

// 3. Fetch rows with 60s Redis query caching enabled
const products = await connection.query("SELECT * FROM products", [], { cache: 60, return_rows: true });

// 4. Debug query execution output
const debug = await connection.query("SELECT * FROM users", [], { debug: true });
// Output:
// [DATABASE DEBUG] SQL: SELECT * FROM users 
// [DATABASE DEBUG] PARAMS: []
// [DATABASE DEBUG] OPTIONS: { debug: true }
// [DATABASE DEBUG] CACHE HIT / MISS

// 5. INSERT query (returns insertId for MySQL, or row ID / rowCount for PostgreSQL)
const newUserId = await connection.query("INSERT INTO users (email) VALUES (?)", ["test@example.com"]);

10 Docker CLI Command Wrapper

Manage development containers and full-stack deployments directly using the built-in Docker CLI tool wrapper. The wrapper dynamically detects whether your project uses MySQL or PostgreSQL based on `getDbType()` reading your .env configuration. 

# Start Development Application Stack (App with live reload + Nginx + Database + Redis)
npx blue-bird docker dev

# Start Production Application Stack (App + Nginx + Database + Redis)
npx blue-bird docker start prod

# Start Configured Database Container Only (Postgres or MySQL)
npx blue-bird docker start db
npx blue-bird docker start postgres
npx blue-bird docker start mysql

# Start Redis Container Only
npx blue-bird docker start redis

# Start Both Databases (Configured DB + Redis)
npx blue-bird docker start dbs

# Stop All Running Project Containers
npx blue-bird docker stop

# Rebuild Node.js Application Production Container Image
npx blue-bird docker build

# Check Active Containers Status
npx blue-bird docker ps

# Tail Live Container Logs
npx blue-bird docker logs
npx blue-bird docker logs db

# Run PM2 Commands Inside the Node.js Application Container
npx blue-bird docker pm2 status
npx blue-bird docker pm2 monit
npx blue-bird docker pm2 reload all

# Run Interactive Shell Inside the Database Container (psql or mysql)
npx blue-bird docker db
npx blue-bird docker psql
npx blue-bird docker mysql

# Run Interactive Redis CLI Connection Inside the Container
npx blue-bird docker redis

# Remove Unused Volumes, Dangling Images, and Buildkit Cache
npx blue-bird docker prune

11 Nginx Static Asset Caching

In production, Nginx is configured to explicitly cache static assets (.js, .css, .jpg, .png, etc.) in the user's browser with the Cache-Control header (valid for 1 month).

HTML and API endpoints (/api/*) are not cached by Nginx to ensure they serve dynamic and up-to-date content, relying instead on the Node.js application and Redis for data-layer caching.

12 Production Setup (VPS / PM2)

Using the built-in Docker stack is the recommended production deployment method. It configures a secure, high-performance reverse proxy via Nginx, offloads static assets directly from disk, prevents common scanner attacks, automatically sets up Redis for caching, and launches Node.js in cluster mode under PM2.

Option A: Docker Deployment (Recommended)

#1. Edit .env , debug=false and PM2_INSTANCES='max' or instances
DEBUG=false
PM2_INSTANCES='max'
# PM2_INSTANCES=1
# PM2_INSTANCES=2

# 2. Build the production image
npx blue-bird docker build

# 3. Run the production containers stack
npx blue-bird docker start prod

Option B: Standalone PM2 Deployment

If running on a standalone server environment outside Docker, you can manage the Node.js application process using PM2. Note that reverse proxies and databases must be configured manually. 

# 1. Install PM2 globally
npm install pm2 -g

# 2. Start the application in production cluster mode
pm2 start index.js --name "blue-bird-app" --node-args="--env-file=.env" -i max

# 3. Save PM2 layout and enable automatic startup on boot
pm2 save
pm2 startup
